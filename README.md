# UiPath Job Manager

A small React app that talks to a .NET 10 middleware API, which in turn calls the
UiPath Orchestrator (Cloud) REST API.

```
frontend/   React + Vite UI  -> http://localhost:5173
backend/    .NET 10 Web API  -> http://localhost:5080  (UiPathMiddleware.sln)
```

The browser never sees your Orchestrator credentials — only the middleware holds them.

## 1. Create an External Application in Orchestrator

Admin -> External Applications -> **Add Application**

* Application Type: **Confidential application**
* Add Application Scope -> Resource: **Orchestrator API Access**, then under
  *Application Scopes* tick: `OR.Folders`, `OR.Jobs`, `OR.Execution`

Copy the **App ID** and **App Secret** (the secret is shown only once).

Then give the application access to your folders:
Tenant -> Folders -> select folder -> *Assign account/group* -> add the external
application with a role that allows viewing and running jobs.

## 2. Configure the backend

Put your real values in `backend/appsettings.Development.json` (git-ignored).
`appsettings.json` stays in source control with placeholders only:

```json
"Orchestrator": {
  "BaseUrl": "https://cloud.uipath.com/YOUR_ORG/YOUR_TENANT/orchestrator_",
  "ClientId": "your-app-id",
  "ClientSecret": "your-app-secret"
}
```

`YOUR_ORG` and `YOUR_TENANT` are the first two path segments of your Orchestrator
URL in the browser, e.g. `https://cloud.uipath.com/acmeltd/DefaultTenant/orchestrator_/`.

ASP.NET merges `appsettings.Development.json` over `appsettings.json` when
`ASPNETCORE_ENVIRONMENT=Development`, which `launchSettings.json` already sets.
For anything beyond local training use `dotnet user-secrets` or environment
variables (`Orchestrator__ClientSecret=...`) instead of a file.

## 3. Run it

Two terminals:

```bash
cd backend
dotnet run
```

(Or open `backend/UiPathMiddleware.sln` in Visual Studio / Rider and hit run.)

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173 for the UI, and http://localhost:5080/swagger for the
API docs (the backend opens Swagger in your browser automatically on `dotnet run`).

## What it does

1. Lists your Orchestrator folders.
2. Pick a folder -> lists the processes and the last 50 jobs in it.
3. Pick a process -> **Start job**.
4. Any running/pending job gets a **Stop** button (SoftStop).

The job table refreshes every 5 seconds.

## Swagger / OpenAPI

* UI: `http://localhost:5080/swagger`
* Document: `http://localhost:5080/openapi/v1.json`

The document is generated by `Microsoft.AspNetCore.OpenApi` (first-party, .NET 10);
`Swashbuckle.AspNetCore.SwaggerUI` only supplies the UI page. You can call every
endpoint straight from Swagger, which is the quickest way to test your credentials
without touching the React app.

## API endpoints (middleware)

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/api/folders` | list folders |
| GET | `/api/folders/{folderId}/processes` | list releases in a folder |
| GET | `/api/folders/{folderId}/jobs` | last 50 jobs in a folder |
| POST | `/api/folders/{folderId}/jobs/start` | body `{ "releaseKey": "..." }` |
| POST | `/api/folders/{folderId}/jobs/{jobId}/stop` | body `{ "strategy": "SoftStop" }` or `"Kill"` |

## Notes

* The OAuth token is cached in memory and refreshed a minute before it expires.
* Folder scoping uses the `X-UIPATH-OrganizationUnitId` header on every call.
* Jobs start with `Strategy: ModernJobsCount` (modern folders). For a classic
  folder you would pass `Strategy: Specific` plus a `RobotIds` list instead.
* `Swashbuckle.AspNetCore.SwaggerUI` is referenced as `9.*` so NuGet picks the
  newest 9.x at restore; pin it to an exact version if you want reproducible builds.
* Don't commit a real secret — use `dotnet user-secrets` or environment variables
  (`Orchestrator__ClientSecret=...`) for anything beyond local training.

## Troubleshooting

**`'<' is an invalid start of a value`** - something returned an HTML page instead
of JSON. Two usual causes:

* `IdentityUrl` must be the full token endpoint:
  `https://cloud.uipath.com/identity_/connect/token` (not just `.../identity_`).
* `BaseUrl` must end in `/orchestrator_`, with your real org and tenant names.

The middleware now names the offending URL in the error message instead of
failing with a bare parse error.

**Empty folder list** - the External Application exists but hasn't been assigned to
any folder. In Orchestrator: Tenant -> Folders -> pick the folder -> *Assign
account/group* -> add the external application.
